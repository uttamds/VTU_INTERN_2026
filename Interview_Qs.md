Here are some solid discussion points/questions you can use when reviewing teams doing their **MERN stack capstone projects**. These help evaluate not just coding, but also design thinking, architecture, teamwork, and real-world readiness.

---

# Capstone Review Discussion Points for MERN Teams

| Area                      | Discussion Points / Questions                                                                               |
| ------------------------- | ----------------------------------------------------------------------------------------------------------- |
| **Problem Understanding** | What real-world problem is your project solving? Why did you choose this problem? Who are the target users? |
| **Project Scope**         | What features are MVP (must-have) vs optional? How did you decide scope?                                    |
| **System Design**         | Why did you choose MERN for this project? Could another stack have worked better?                           |
| **Frontend Architecture** | How have you structured your React components? Why? How are you managing reusable UI?                       |
| **State Management**      | How are you managing state? (`useState`, Context API, Redux, Zustand etc.) Why that approach?               |
| **Backend Design**        | How is your Express backend structured? Are routes/controllers/services separated properly?                 |
| **Database Design**       | Why did you structure MongoDB collections this way? How are relationships handled?                          |
| **Authentication**        | How are users authenticated? JWT/session? Why? How is password security handled?                            |
| **Authorization**         | Do different users have roles/permissions? How is access controlled?                                        |
| **API Design**            | Are your APIs RESTful? Why did you choose certain endpoints?                                                |
| **Validation**            | Where is input validation handled—frontend/backend/both? Why?                                               |
| **Error Handling**        | How are errors managed and communicated to users?                                                           |
| **Performance**           | What performance optimizations have you considered? (pagination, lazy loading, indexing, caching)           |
| **Security**              | How are you handling XSS, CORS, injection, env variables, sensitive data?                                   |
| **Testing**               | Have you tested your APIs/components? Manual or automated?                                                  |
| **Git Workflow**          | How is your team using Git/GitHub? Branch strategy? PR reviews?                                             |
| **Deployment**            | Where will the app be deployed? What challenges in deployment?                                              |
| **Scalability**           | If user base grows 100x, what part breaks first? How would you improve?                                     |
| **Challenges Faced**      | Biggest technical blocker faced? How did you solve it?                                                      |
| **Learnings**             | What new concept/technology did you learn during this project?                                              |
| **Future Enhancements**   | If given 1 more month, what would you improve/add?                                                          |

---

# Deeper Technical Mentor Questions (to push stronger students)

| Topic        | Advanced Prompt                                      |
| ------------ | ---------------------------------------------------- |
| React        | Why not keep all state in one parent component?      |
| MongoDB      | Why use NoSQL here instead of SQL?                   |
| Backend      | How would you refactor if microservices were needed? |
| Security     | What if token gets stolen—how do you mitigate?       |
| Optimization | How would app behave with 1 lakh records?            |
| Architecture | What design patterns are you using?                  |
| DevOps       | How would CI/CD help your project?                   |

---

# Team / Professionalism Discussion

| Area                | Prompt                                           |
| ------------------- | ------------------------------------------------ |
| Collaboration       | How did team divide work?                        |
| Ownership           | Who handled what module and why?                 |
| Conflict Resolution | Did disagreements occur? How resolved?           |
| Time Management     | How are deadlines tracked?                       |
| Documentation       | Have you documented APIs / setup / architecture? |

---

# Great Reflection Question to End With

Ask every team:

> **"If this project were for a real paying client tomorrow, what would you change before delivery?"**

This often triggers mature thinking about polish, security, testing, and maintainability.

---

If you're mentoring engineering students, I can also convert this into a **weekly capstone review checklist format** (Week 1/2/3/4 mentor meeting agenda) so you can track them throughout the project lifecycle.
